\section{Introduction}

Cyber-physical systems (CPS) tightly integrate computation, communication, and physical processes. Industrial control systems, smart manufacturing environments, and automated production lines increasingly depend on programmable logic controllers (PLCs), sensors, actuators, and supervisory software to maintain correct and safe operation. At the same time, recent progress in large language models (LLMs) has introduced new possibilities for automation, reasoning, and system interaction. These advances raise an important question: can LLMs be used in a principled way to study both offensive and defensive CPS behaviour under realistic process constraints?

Existing work on LLMs for CPS security remains limited in several important ways. First, studies such as AttackLLM~\cite{ahmed2025attackllm} generate attack patterns offline and evaluate them on static datasets, which do not capture the timing behaviour and control feedback of a live control loop. Second, autonomous cyber agents like PentestGPT~\cite{deng2024pentestgpt} and Hackphyr~\cite{rigaki2024hackphyr} target IT infrastructure rather than physics-constrained industrial processes. Third, adaptive defence frameworks such as Evo-Defender~\cite{hu2025evodefender} co-evolve attackers and defenders through fuzzing but do not employ LLMs, while multi-agent LLM systems like MALF~\cite{ning2025malf} operate at the protocol level rather than the process level. As a result, it remains unclear how effective LLM-generated CPS attacks are when grounded in real process context, how safely such attacks can be evaluated, and whether defenders---including LLM-based defenders---can systematically improve from attack-induced failures.

This paper proposes \textbf{CPSForge}, a closed-loop LLM red-team/blue-team CPS testbed designed to address these gaps. CPSForge is built around a real Siemens S7 PLC connected to Factory~I/O, with control logic engineered in TIA Portal~v17. The framework supports two operational modes. In \emph{batch mode}, scripted, random, or LLM-based attackers propose structured attack actions---sensor spoofing, actuator overrides, setpoint shifts, timing perturbations, or sequence disruptions---through an orchestrated pipeline, with every action mediated by a configurable runtime safety shield before any write reaches the PLC. In \emph{live agent mode}, an autonomous LLM attacker agent and an LLM defender agent run as independent concurrent processes. The attacker agent observes plant state and proposes attacks while the defender agent monitors telemetry and proposes corrective actions, both coordinated through a central mediator that enforces safety constraints on all writes.

On the defensive side, CPSForge supports threshold-based, invariant-based, and learned detectors, as well as an LLM defender agent that can reason over process context and propose corrective interventions. The core closed-loop idea is that unsuccessful detections are not isolated failures: missed or weakly detected attacks are collected into a hard-case bank and used to refine the defender over repeated rounds.

The contributions of this paper are as follows:

\begin{itemize}[leftmargin=1.5em]
    \item We present CPSForge, a closed-loop LLM red-team/blue-team testbed for cyber-physical systems built around a real Siemens S7 PLC and Factory~I/O hardware-in-the-loop environment.
    \item We introduce a structured CPS attack framework in which an LLM proposes process-aware attack actions while a configurable runtime safety shield mediates all live writes.
    \item We design a \emph{live agent mode} in which an autonomous LLM attacker and an LLM defender operate as independent concurrent agents on the same physical process, coordinated through a safety-enforcing mediator.
    \item We implement a closed-loop defender workflow that supports hard-case collection and iterative adaptation across repeated attack rounds.
    \item We evaluate CPSForge across three Factory~I/O scenes using four attacker variants (scripted, random, LLM batch, LLM agent) and three defender configurations, demonstrating measurable attack impact, safety shield mediation, detection performance, and adaptation gains under live PLC execution.
\end{itemize}
