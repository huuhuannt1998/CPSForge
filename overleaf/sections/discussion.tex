\section{Discussion}
\label{sec:discussion}

\subsection{Why Real PLC Execution Matters}

A central design choice in CPSForge is the use of a real Siemens S7 PLC rather than a purely synthetic or mock controller. This choice increases implementation complexity but strengthens evaluation realism. Real controller scan timing, actual tag behaviour, and live interaction with Factory~I/O provide a more faithful substrate for studying both attack validity and defence response. For a framework focused on LLM use in CPS security, this realism is important because it reduces the risk that observed results are artefacts of an oversimplified backend. Prior HIL testbeds~\cite{dehlaghi2023icssim, garcia2025sphere, pramadi2026simpleics} establish this principle; CPSForge extends it to LLM-driven experimentation.

\subsection{Why the LLM Is Constrained}

CPSForge intentionally avoids treating the LLM as a trusted autonomous controller. This is both a safety decision and a research decision. From a safety perspective, unrestricted direct actuation is inappropriate in a live CPS setting~\cite{lanotte2022runtime_ics, baird2024scalable_enforcement}. From a research perspective, a structured and mediated interface makes it possible to evaluate the LLM's reasoning quality without conflating model output quality with uncontrolled execution privilege. The framework therefore studies what the LLM can contribute under explicit process and safety constraints.

\subsection{Observed Strengths}

The evaluation confirms several strengths. First, the hardware-in-the-loop environment produces measurable process impact: across 55~runs and 4{,}465~time-series steps, all scripted and random attacks executed successfully on the live Siemens S7-1200, with scripted attacks achieving ASR~=~1.0 on Level Control. Second, the LLM batch attacker generated process-valid attacks with 100\% action validity and execution success across all scenes, confirming that structured prompting with JSON schema validation can reliably translate LLM reasoning into concrete PLC operations. Third, the safety shield mediated all writes across all configurations, rejecting only random out-of-range actions (20\% on Sorting) and permitting no unsafe execution. Fourth, the threshold and invariant detectors achieved perfect recall (1.0) across all batch-mode runs, detecting every attack step---a strong baseline for the closed-loop adaptation mechanism.

The multi-agent architecture successfully demonstrated concurrent attacker and defender agent operation through the full PLC loop, with independent LLM inference, shield validation, and PLC I/O. The infrastructure supports the closed-loop workflow even when the underlying LLM model is the performance bottleneck.

\subsection{Limitations}

The current evaluation has several limitations.

\textbf{Agent-mode model capacity.} The agent-mode experiments used Phi-3-Mini-4K-Instruct (3.8B parameters) due to context-window constraints with larger local models. This model achieved only 1.6--2.1\% schema compliance, producing valid structured actions in 1 out of 47--61 attacker cycles per scene. The primary failure modes were targeting tags not on the attack surface, missing required JSON keys, and producing unstructured text. A schema normalisation layer (key aliasing, type aliasing, nested unwrapping) recovered some borderline outputs, but the model's limited instruction-following capacity was the binding constraint. Larger models with native function-calling support (e.g., 13B+ instruction-tuned models, GPT-4, or Claude) would substantially improve agent-mode effectiveness. This result itself is informative: it establishes a lower bound on model size for effective CPS agent operation.

\textbf{Detector precision.} Detector precision ranged from 0.01 to 0.70 across configurations, with high false positive counts (49--198 per run). The threshold detector fires conservatively on any state deviation, producing many false alarms during normal process variation. This underscores the need for adaptive threshold calibration~\cite{moriano2025adaptive_anomaly} and learned anomaly scoring to reduce false positive rates to operationally acceptable levels.

\textbf{Sorting scene resilience.} No attacker variant achieved non-zero ASR on Sorting by Height Sorting, reflecting this scene's inherent resilience to single-tag perturbations in discrete-control processes. More sophisticated multi-step or multi-tag attack strategies, potentially with hierarchical LLM planning, are needed to effectively attack complex discrete scenes.

\textbf{Constrained action space.} Attacks are bounded by the configured attack surface, duration caps, and cooldown windows enforced by the shield. While essential for safety, this limits the attacker's ability to sustain long-duration perturbations or target arbitrary tags. Future work should explore graduated relaxation of these constraints in controlled settings.

\textbf{Single LLM per mode.} The batch-mode evaluation uses Qwen2-7B-Instruct and agent mode uses Phi-3-Mini-4K-Instruct. Comparing across multiple LLM backends---including larger open-source models and API-served models---would strengthen generalisability claims and disentangle model capability from framework capability.

\subsection{Comparison to Most Related Work}

Compared to AttackLLM~\cite{ahmed2025attackllm}, CPSForge operates in a live PLC loop rather than offline, includes a safety shield and defender stack, and supports closed-loop adaptation. Compared to Evo-Defender~\cite{hu2025evodefender}, CPSForge uses LLM reasoning rather than fuzzing for attack generation and runs on a real PLC rather than a simulator. Compared to PentestGPT~\cite{deng2024pentestgpt} and Hackphyr~\cite{rigaki2024hackphyr}, CPSForge targets CPS process-level attacks rather than IT-infrastructure exploitation. No prior work in our survey combines all seven capabilities listed in Table~\ref{tab:comparison}.

\subsection{Future Directions}

Several extensions are planned. First, evaluating larger LLM backends (13B+ open-source, GPT-4, Claude) to assess the influence of model capacity on attack quality, schema compliance, and defence reasoning---our results show that 3.8B models are insufficient for reliable structured CPS agent operation while 7B models succeed in batch mode. Second, extending the agent mode to support multi-round \emph{campaigns} where the attacker maintains persistent objectives across many interaction cycles, leveraging the infrastructure already demonstrated. Third, reducing detector false positives through adaptive threshold calibration, learned anomaly scoring, and the adaptation loop with accumulated hard cases. Fourth, expanding to additional Factory~I/O scenes and more complex PLC programs. Fifth, integrating LLM-assisted invariant synthesis to automatically derive scene-specific detector rules from PLC documentation or runtime traces.
