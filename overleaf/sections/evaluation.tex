\section{Evaluation}
\label{sec:evaluation}

This section presents experimental results from live PLC-based runs across five Factory~I/O scenes using five attacker variants, multiple defender configurations, and a closed-loop adaptation protocol. All reported numbers are collected from eval runs on the real Siemens S7-1200 PLC connected to Factory~I/O.

\subsection{Research Questions}

\begin{description}[leftmargin=1.5em, style=nextline]
    \item[RQ1:] Can structured attackers---including LLM-based attackers---generate process-valid attack actions that execute successfully in the live PLC--Factory~I/O loop?
    \item[RQ2:] How does attacker effectiveness vary across attacker types (scripted, random, LLM batch, campaign, LLM agent) and scenes?
    \item[RQ3:] How effective is the safety shield at blocking unsafe or invalid actions while preserving useful experimental attack coverage?
    \item[RQ4:] How well do the defender configurations detect attack-induced anomalies under live execution?
    \item[RQ5:] Does the multi-agent mode exhibit qualitatively different dynamics compared to batch-mode attackers?
    \item[RQ6:] Does closed-loop adaptation improve defender robustness over repeated rounds?
    \item[RQ7:] How do classical, statistical, and learned anomaly detectors compare when evaluated on the same live attack traces?
\end{description}

\subsection{Evaluation Environment}

Experiments are conducted on a real Siemens S7-1200 PLC connected to Factory~I/O~\cite{factoryio} through TIA Portal~v17~\cite{tiaportal}. The evaluation covers five scenes: From A to B (discrete conveyor transport, 4~tags), Filling Tank (discrete fill-cycle process, 8~tags), Level Control (continuous tank process, 15~tags), Sorting by Height (mixed discrete-sort process, 30~tags), and Sorting by Weight (threshold-based sorting process, 35~tags). The middleware polls PLC tags at 500\,ms intervals via python-snap7~\cite{snap7}. Each experiment run produces structured artifacts including a time-series trace (Parquet), attack records, shield decisions, detection events, and summary metrics (all JSON). LLM-based attackers in batch mode use a local Qwen2-7B-Instruct model served via LM Studio; agent-mode and campaign-mode experiments use Qwen2-7B-Instruct for the attacker agent. Across all experiments, we collected 96~runs from 54~experiment configurations, comprising 68~eval-flagged runs (including 8~defense-ablation runs), 12~adaptation rounds, and 16~development runs, totalling 11{,}864~time-series steps from the live PLC loop. A total of 207~attack actions were executed across three attack types: actuator override (143), setpoint shift (43), and sequence perturbation (21). The framework additionally supports sensor spoofing and timing delay actions, but these were not triggered by the attacker configurations used in this evaluation. Figure~\ref{fig:dataset} summarises the dataset composition.

\subsection{Attacker Configurations}

We compare five attacker variants:

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Scripted:} manually defined attack templates targeting specific process-critical tags.
    \item \textbf{Random:} bounded random perturbations over the configured attack surface.
    \item \textbf{LLM (batch):} an LLM receives scene context and plant state and proposes structured attack actions through the single-shot pipeline.
    \item \textbf{Campaign:} a four-phase LLM-driven attacker that executes structured multi-step attack sequences (reconnaissance, preparation, exploitation, persistence), evaluated on Level Control and Sorting by Weight.
    \item \textbf{LLM (agent):} an autonomous LLM attacker agent operates concurrently with an LLM defender agent in the multi-agent mode.
\end{itemize}

The defender side uses threshold and invariant detectors for all batch-mode runs. In agent mode, an LLM defender agent additionally monitors process state and proposes corrective actions. For the cross-detector comparison (RQ7), we additionally evaluate CUSUM, One-Class SVM (OCSVM), Isolation Forest, and LSTM autoencoder detectors on the same live attack traces collected from Level Control and Sorting by Weight scenes. The ML-based detectors (OCSVM, Isolation Forest, LSTM-AD) are trained on 300-step baseline traces collected during normal plant operation.

\subsection{Metrics}

Attack metrics use explicit denominators: action validity ($N_{\text{schema}}/N_{\text{sub}}$), execution success rate ($N_{\text{exec}}/N_{\text{appr}}$), and attack success rate ASR ($N_{\text{succ}}/N_{\text{exec}}$). A successful attack is one that crosses the scene-specific deviation threshold $\epsilon$ in at least one monitored tag during attack-active windows. The impact score is the mean normalized deviation metric defined in Section~\ref{sec:methodology}. Shield metrics are approval and rejection rates; defender metrics are precision, recall, F1, false positive count, false negative count, and detection latency. All tabulated values are rounded to two decimals.

\paragraph{RQ1: Attack Validity and Execution.}
Scripted and random attackers produced process-valid actions, and every shield-approved action executed successfully on the live Siemens S7-1200. LLM batch actions achieved 100\% action validity and 100\% execution success conditioned on shield approval across all five scenes, with every approved action compiled to concrete tag writes. This confirms end-to-end pipeline correctness: the structured action schema, JSON validation with retry, and shield mediation reliably translate LLM outputs into legitimate PLC operations. Shield rejections in constrained scenes (Table~\ref{tab:shield-results}) are explicitly accounted for and do not count as execution failures.

\paragraph{RQ2: Attack Effectiveness Across Types and Scenes.}
Scripted attacks are most effective when critical process tags are targeted: on Level Control, scripted achieves ASR~=~0.75 with impact~=~1.00, exploiting domain knowledge of tank fill/discharge dynamics. Random attacks achieve higher coverage (10 actions per run) and match scripted effectiveness on Level Control (ASR~=~0.75). The LLM batch attacker generated fewer but targeted actions (1--3 per run), achieving ASR~=~0.33 on Level Control and ASR~=~0.50--0.67 on From A to B and Sorting by Weight, demonstrating comparable per-action effectiveness with fewer actions.

Two scenes show distinct patterns: Level Control is the most consistently exploitable scene, with all three attacker types achieving high ASR (0.33--0.75) and measurable impact. Sorting by Weight showed the highest LLM batch ASR (0.67), exploiting threshold parameters that the model correctly identified as process-critical. Sorting by Height proved most resilient, with LLM batch scoring zero ASR and scripted/random achieving ASR $\leq$ 0.12, reflecting the difficulty of disrupting discrete sorting logic through single-tag perturbations.

The campaign attacker executes structured four-phase attacks (reconnaissance, preparation, exploitation, persistence) over 8--10 actions per run. On Level Control, a dedicated campaign stress run achieved a stealth score of 1.0---every attack step evaded both threshold and invariant detectors (102~false negatives, F1~=~0.0), despite an ASR of only 0.22 and moderate impact (0.14). This result primarily exposes a known limitation of rule-based detectors: gradually-escalating perturbations that remain within configured threshold bounds are invisible to fixed-threshold monitors. The campaign's multi-phase planning enabled it to stay within these bounds, but the evasion mechanism is detector blindness rather than adversarial sophistication per se. On Sorting by Weight, the campaign achieved higher ASR (0.78) but zero stealth (all attacks detected, F1~=~0.65), indicating that stealth and effectiveness are scene-dependent properties. The stress-run result above is separate from the adaptation rounds reported later in Table~\ref{tab:adapt-results}.

\paragraph{RQ3: Shield Effectiveness.}
The shield approved 100\% of LLM batch actions across all scenes. Shield rejections occurred with scripted attacks on From A to B (20\% rejected) and Sorting by Weight (20\% rejected), and with random attacks on Sorting by Height (20\% rejected) and Sorting by Weight (30\% rejected), where tag ranges impose tighter constraints. In Level Control agent mode, the shield rejected 21 of 25 submitted actions (84\%), reflecting its strict process invariants. No unsafe writes were permitted across any configuration, confirming the shield's role as a hard safety boundary.

\paragraph{RQ4: Detection Performance.}
Table~\ref{tab:defender-results} reports the \emph{union} of threshold and invariant detector alerts: a step is flagged as detected if either detector fires. Threshold and invariant detectors achieve perfect recall (1.0) in most batch-mode configurations, meaning no attack step was missed. Precision varies widely: highest for Sorting by Weight scripted (0.87, F1~=~0.93) and lowest for LLM batch runs on scenes with few attack steps relative to run length (F1 $\leq$ 0.05 in several cases). The low LLM batch F1 values (0.05--0.24) stem from a detector calibration mismatch: the threshold detector fires on \emph{any} state deviation, and in runs with only 1--3 short-duration attacks across 120+ steps, the resulting false-positive counts (113--164) overwhelm the few true positives. This indicates that the current threshold settings, while effective for scripted and random attacks, are over-sensitive for sparse attack patterns and would benefit from adaptive calibration.

Level Control random is a notable case where recall drops to 0.52 (FN~=~59), as frequent small-magnitude setpoint perturbations fall within normal process variation bounds. The false-positive counts (13--164) reflect the threshold detector's conservative design and motivate the adaptation loop experiments summarised in Table~\ref{tab:adapt-results}.

\paragraph{RQ5: Agent Mode Dynamics.}
The multi-agent architecture with Qwen2-7B-Instruct successfully executes concurrent attacker and defender processes with independent LLM inference, coordinated through a single PLC-owning coordinator. Using a larger model than prior experiments, the attacker agent achieved 95--98\% shield approval rates across four of five scenes: 29/30 approved on From A to B, 19/20 on Filling Tank, 38/39 on Sorting by Height, and 44/45 on Sorting by Weight. This represents a dramatic improvement over the initial Phi-3-Mini-4K-Instruct runs that achieved only 2\% schema compliance.

Level Control remains the exception: only 3 of 25 submitted actions (12\%) were approved by the shield, due to strict process invariant rules that reject any action deviating from tight level bounds. This result demonstrates the shield's correct enforcement of safety constraints even when the attacker explicitly reasons about the attack surface and value ranges. Across all five scenes, attacker errors dropped to zero---confirming that the Qwen2-7B model reliably generates structurally valid JSON actions when provided with range-annotated attack surface descriptions. The defender agent emitted 31--100 detection events per scene, providing continuous monitoring coverage.

\paragraph{RQ6: Adaptation.}
We ran two sets of three-round closed-loop adaptation experiments on Level Control and Sorting by Weight. The first set used scripted and random attackers; the second used the campaign attacker to stress-test adaptation against harder attack distributions. Table~\ref{tab:adapt-results} summarises the campaign adaptation results.

With scripted and random attackers, the threshold and invariant detectors maintained stable F1 scores across all rounds without retraining (Level Control: F1~=~0.916, Recall~=~1.0; Sorting by Weight: F1~=~0.925, Recall~=~1.0), and zero hard cases were flagged. This confirms that rule-based detectors are well-calibrated for predetermined attack patterns.

With the campaign attacker, Level Control exhibited dramatic adaptation dynamics. In Round~0, the campaign completely evaded all detectors (F1~=~0.00, Recall~=~0.00), with every one of 102~attack steps classified as a false negative. The Isolation Forest detector was retrained on these hard-case windows plus synthetic normal data. In Round~1, detection performance jumped to F1~=~0.92 (Precision~=~0.84, Recall~=~1.00). This result should be interpreted cautiously: the retrained detector was evaluated on a \emph{new} campaign run, but the campaign planner used the same LLM and scene configuration, so the Round~1 attacks likely share structural similarity with Round~0. The single-round recovery demonstrates that hard-case retraining can close a specific coverage gap, but does not establish generalisation to structurally different attack sequences. Round~2 sustained this performance (F1~=~0.92, zero new hard cases), yielding a net improvement of $+$0.92 F1 from Round~0.

On Sorting by Weight, the detectors achieved perfect recall (1.00) from Round~0 onward, with zero hard cases across all three rounds---no attacks were missed. No retraining was triggered. ASR decreased from 0.78 in Round~0 to 0.13 in Rounds~1--2, and detection precision improved correspondingly (F1: 0.65$\to$0.92). Because no retraining occurred, these metric changes reflect variability in the LLM-planned campaign phases across rounds rather than detector adaptation. The contrasting results demonstrate that adaptation is most valuable in scenes where initial detectors have coverage gaps---precisely the scenarios where campaign attackers can discover evasive sequences.

\paragraph{RQ7: Cross-Detector Analysis.}
As shown in Figure~\ref{fig:detector-comparison}, the one-class ML detectors (OCSVM and Isolation Forest) achieve the highest F1 scores on both scenes, driven by perfect or near-perfect recall: every attack step is flagged as anomalous relative to the learned normal distribution. However, their precision is modest (0.49--0.56), as the models also flag some normal process variation as anomalous. OCSVM and Isolation Forest both achieve sub-second detection latency because they score each snapshot independently without requiring temporal context.

LSTM-AD provides the best precision--recall trade-off among learned detectors (F1~=~0.601 on Level Control, 0.542 on Sorting by Weight), with the reconstruction-error threshold capturing temporal anomalies that point-wise detectors cannot distinguish from noise. Its detection latency of 1.4--3.1\,s reflects the sliding-window requirement for the autoencoder.

CUSUM provides interpretable statistical change detection but exhibits higher latency (4.5--6.4\,s) due to the cumulative-sum warmup period before the statistic exceeds its threshold. Its recall is lower (0.48--0.59) because short-duration attacks may not accumulate sufficient deviation.

The threshold detector remains competitive (F1~=~0.48--0.52), confirming its value as a zero-training baseline. The invariant detector shows the highest precision among rule-based approaches on Sorting by Weight (0.626) but the lowest recall on Level Control (0.169), reflecting its conservative scene-specific rules that miss subtle perturbations.

These results indicate that even with minimal training data (300 steps), one-class ML detectors provide measurable detection improvements over hand-tuned baselines. Longer baseline traces would likely improve all ML detector scores; the current comparison establishes relative ordering rather than ceiling performance. The diversity of detector characteristics---particularly the precision--recall and latency trade-offs---motivates ensemble approaches in future work.

\subsection{Defense Ablation}
\label{sec:ablation}

To isolate the contribution of each detector class, we ran eight dedicated PLC experiments using four defender configurations on Level Control and Sorting by Weight: (i)~threshold detector only, (ii)~invariant detector only, (iii)~ML detectors only (OCSVM + Isolation Forest), and (iv)~full ensemble (all four detectors). Each run uses the scripted attacker with 150 steps (Level Control) or $\approx$118 steps (Sorting by Weight). Table~\ref{tab:ablation} reports the results.

On Level Control, the threshold detector alone achieves full recall (F1~=~0.75) but at the cost of 60~false positives, while the invariant detector contributes nothing (F1~=~0.00)---its rules target valve interlock violations that the scripted attacker does not trigger. The ML-only configuration matches the threshold detector's performance (F1~=~0.75, recall~=~1.0), and the full ensemble offers no additional gain, indicating that the threshold and ML detectors cover the same attack patterns on this scene. Notably, ASR rises from 0.25 to 0.50 under ML-only and full-ensemble configurations; this reflects run-to-run variability in the scripted attacker's random target selection rather than a detector weakness.

On Sorting by Weight, all four configurations achieve perfect recall. The invariant detector alone yields the highest precision (0.88, F1~=~0.93) with only 14~false positives, because its weight-threshold rules align well with the scene's attack surface. The threshold, ML-only, and full-ensemble configurations produce similar F1 ($\approx$0.91) with slightly more false positives (20). The threshold-only configuration is the only one to achieve ASR~=~0.00, suggesting that its conservative alerting indirectly constrains the effective attack window.

\subsection{Benign False-Positive Rate}
\label{sec:benign-fp}

We evaluated all configured detectors on baseline (attack-free) traces from six Factory~I/O scenes to quantify the false-positive rate under normal plant operation. Across 87 detector--trace evaluations, the aggregate false-positive rate was \textbf{0.0001} (one detection event per 10{,}000 benign steps). The threshold, invariant, and CUSUM detectors produced zero false positives on all baseline traces. ML-based detectors without pre-trained models (untrained OCSVM, Isolation Forest, LSTM-AD) also produced zero false alerts. This near-zero FP rate confirms that the detector configurations are well-calibrated for normal process behavior and that detected anomalies during attack experiments reflect genuine deviations rather than detector noise.
