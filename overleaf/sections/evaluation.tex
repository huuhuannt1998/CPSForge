\section{Evaluation}
\label{sec:evaluation}

This section presents experimental results from live PLC-based runs across three Factory~I/O scenes using four attacker variants and multiple defender configurations. All reported numbers are collected from eval runs on the real Siemens S7-1200 PLC connected to Factory~I/O.

\subsection{Research Questions}

\begin{description}[leftmargin=1.5em, style=nextline]
    \item[RQ1:] Can structured attackers---including LLM-based attackers---generate process-valid attack actions that execute successfully in the live PLC--Factory~I/O loop?
    \item[RQ2:] How does attacker effectiveness vary across attacker types (scripted, random, LLM batch, LLM agent) and scenes?
    \item[RQ3:] How effective is the safety shield at blocking unsafe or invalid actions while preserving useful experimental attack coverage?
    \item[RQ4:] How well do the defender configurations detect attack-induced anomalies under live execution?
    \item[RQ5:] Does the multi-agent mode exhibit qualitatively different dynamics compared to batch-mode attackers?
    \item[RQ6:] Does closed-loop adaptation improve defender robustness over repeated rounds?
\end{description}

\subsection{Evaluation Environment}

Experiments are conducted on a real Siemens S7-1200 PLC connected to Factory~I/O~\cite{factoryio} through TIA Portal~v17~\cite{tiaportal}. The evaluation covers three scenes: From A to B (discrete conveyor transport, 4~tags), Level Control (continuous tank process, 15~tags), and Sorting by Height (mixed sorting process, 30~tags). The middleware polls PLC tags at 500\,ms intervals via python-snap7~\cite{snap7}. Each experiment run produces structured artifacts including a time-series trace (Parquet), attack records, shield decisions, detection events, and summary metrics (all JSON). LLM-based attackers in batch mode use a local Qwen2-7B-Instruct model served via LM Studio; agent-mode experiments use Phi-3-Mini-4K-Instruct (3.8B parameters) due to context-window constraints. Across all experiments, we collected 55~runs totalling 4{,}465~time-series steps from the live PLC loop. Figure~\ref{fig:dataset} summarises the dataset composition.

\subsection{Attacker Configurations}

We compare four attacker variants:

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Scripted:} manually defined attack templates targeting specific process-critical tags.
    \item \textbf{Random:} bounded random perturbations over the configured attack surface.
    \item \textbf{LLM (batch):} an LLM receives scene context and plant state and proposes structured attack actions through the single-shot pipeline.
    \item \textbf{LLM (agent):} an autonomous LLM attacker agent operates concurrently with an LLM defender agent in the multi-agent mode.
\end{itemize}

The defender side uses threshold and invariant detectors for all batch-mode runs. In agent mode, an LLM defender agent additionally monitors process state and proposes corrective actions.

\subsection{Metrics}

Attack metrics: action validity rate, execution success rate, attack success rate (ASR), and process impact score. Shield metrics: approval rate and rejection rate. Defender metrics: precision, recall, F1, false positive count, false negative count, and detection latency.

\paragraph{RQ1: Attack Validity and Execution.}
All scripted and random attacks compiled to valid PLC writes and executed successfully on the live Siemens S7-1200. LLM batch actions achieved 100\% action validity and execution success across all three scenes, with every generated action successfully compiled to concrete tag writes. The structured action schema and JSON validation with retry ensure that all LLM outputs map to legitimate PLC operations. Across all batch-mode experiments, every submitted action that passed shield validation was successfully executed on the physical PLC.

\paragraph{RQ2: Attack Effectiveness Across Types and Scenes.}
Scripted attacks are most effective when critical tags are known: on Level Control, scripted achieves ASR~=~1.0 with impact~=~1.45, exploiting domain knowledge of the tank fill/discharge dynamics. Random attacks are effective at volume (10~actions per run) but achieve lower per-attack success: ASR~=~0.80 and impact~=~0.98 on Level Control, ASR~=~0.30 on From A to B. The LLM batch attacker generated fewer but targeted actions (1--3 per run), achieving ASR~=~0.33 and impact~=~1.0 on Level Control---comparable to random in fewer actions---while hitting a 0.30 impact on From A to B despite zero ASR, indicating partial process disruption even on failed attacks.

On the Sorting scene, no attacker variant achieved non-zero ASR or impact, reflecting this scene's resilience to the attack types evaluated. The sorting process operates on discrete items with independent control paths, making single-tag perturbations less likely to corrupt overall throughput.

\paragraph{RQ3: Shield Effectiveness.}
The shield approved 100\% of scripted attacks (which are designed to respect safety bounds) and 100\% of LLM batch actions across all scenes, indicating that the LLM learned to produce in-range, whitelist-compliant actions. The only shield rejections occurred with random attacks on Sorting (20\% rejected), where random target selection occasionally hit tags outside the writable whitelist or exceeded configured bounds. No unsafe writes were permitted across any configuration, confirming the shield's role as a hard safety boundary. In agent mode, all actions that passed schema validation (1 per scene) were approved by the shield.

\paragraph{RQ4: Detection Performance.}
Threshold and invariant detectors achieve perfect recall (1.0) across all batch-mode configurations, meaning no attack step was missed. However, precision varies significantly: highest for random attacks on Sorting (0.70, F1~=~0.82) and lowest for LLM batch attacks on scenes with few attack steps relative to total steps (0.01 on From A to B with 150 steps and only 1 attack). The high false positive counts (49--198) reflect the threshold detector's conservative design: it fires on any state deviation exceeding a fixed bound, including normal process variation. This over-alerting pattern is consistent across all scenes and motivates the adaptation loop for improving detector specificity.

\paragraph{RQ5: Agent Mode Dynamics.}
The multi-agent architecture successfully executes concurrent attacker and defender agents with independent PLC connections and LLM inference. Each agent cycle involves a full LLM call with scene context, plant snapshot, and history---demonstrating the system's ability to maintain real-time closed-loop operation.

However, the local Phi-3-Mini-4K-Instruct model (3.8B parameters) exhibited only 1.6--2.1\% schema compliance, producing valid structured attack actions in 1 out of 47--61 attacker cycles per scene. The primary failure modes were: (1) targeting tags not on the attack surface (e.g., \texttt{stop\_light} instead of configured actuators), (2) missing required JSON keys, and (3) producing non-JSON text. The schema validator's normalisation layer (key aliasing, type aliasing, nested unwrapping) recovered some borderline outputs, but the model's limited capacity for strict instruction-following under context constraints was the binding limitation. Larger models (7B+) with native JSON/function-calling support would significantly improve agent-mode effectiveness.

Despite low action throughput, the agent infrastructure operated correctly: all valid actions were shielded, executed on the PLC, and defended against. The defender agent emitted detections on 40--52 of 100 steps, providing continuous monitoring coverage.

\paragraph{RQ6: Adaptation.}
The hard-case bank accumulated misdetected and borderline traces from evaluation runs. The current evaluation represents adaptation round~0 (initial detectors without retraining). With perfect recall across all batch-mode runs (zero false negatives), the primary adaptation target is precision improvement: reducing the 49--198 false positives per run by tuning thresholds or retraining the sequence detector on accumulated normal-operation traces. The agent-mode runs, where the attacker produced fewer and more targeted perturbations, closely approximate the hard-case conditions where adaptation offers the greatest benefit.
